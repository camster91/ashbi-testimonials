# display: honest review schema

T08 separates display from structured-data eligibility. Existing manual/imported reviews have unknown provenance, so retain their display but do not treat them as directly collected ratings automatically. Add `origin` = `direct`, `manual`, `imported`; public form saves `direct`, ordinary administrative creation defaults `manual`, CSV imports default `imported`. Existing origin is preserved when editing a review unless explicitly changed. A manager may attest direct collection in the editor; source URL or a named external review platform always makes a review ineligible regardless of origin. Export origin for portability but imported files cannot grant direct trust automatically.

Shortcode aggregate schema requires a visible rating summary, a single explicitly identified product/software entity and uncurated filters: no IDs, minimum-rating, featured, verified-only or random showcase. If any rated matching review is not eligible, omit Ashbi schema for that view instead of publishing an average that differs from the visible display. Self-serving business collections remain excluded. WooCommerce only adds Ashbi ratings to its existing native schema if all rated Ashbi reviews for the product are eligible. Otherwise leave native schema alone. No guaranteed search stars.

Use one grouped eligibility count in the existing stats query/cache key, not an unbounded per-review scan. Core post/meta storage remains. Tests: eligible direct reviews generate markup with a visible summary; imported/external/missing provenance, hidden summary, curated selection and business collections do not; native WooCommerce markup remains intact. Document migration behaviour and the administrator attestation explicitly. Official policy: https://developers.google.com/search/docs/appearance/structured-data/review-snippet .
