# Opt-in pilot protocol — participation pending

No pilot sites, retention results or customer endorsements are claimed. Cameron must authorise recruitment, select the approved release and assign support ownership. Do not contact anyone automatically.

Start with 10–20 consenting sites: brochure/service, content, WooCommerce legacy orders, WooCommerce HPOS, multisite, Elementor and native block themes; include shared hosting, persistent object cache, a page cache/CDN and an RTL locale. Record the owner's permission, site category, versions, install date, configuration, observed failures, recovery outcome and follow-up owner. Use an internal identifier; avoid public domains, customer data and exported reviews in the shared scorecard.

Each participant installs on staging, completes the operations guide unaided, imports/exports a small fictional set, submits/moderates a review, checks private data, verifies keyboard/mobile output, rehearses rollback and tests email only through a sink before authorising real opt-in reminders. Record time-to-first-published-review, blocking errors, data discrepancies, assistance needed, page/server timings under declared conditions and accessibility observations.

At days 7 and 30, collect permission-based feedback: still using it, why/why not, workflow friction and support effort. Retained use means the plugin remains active with a real approved collection displayed; an installation alone is not retention. Maintain an issue owner and resolution evidence for every blocker. No adoption targets or dates are results until actually observed.

Expand to 100 only after no unresolved high-impact privacy/data-loss/trust issues, reproducible upgrade/recovery, transparent performance limitations, design acceptance and confirmed support capacity. Million-site suitability requires evidence beyond this pilot; no benchmark can prove it alone.
